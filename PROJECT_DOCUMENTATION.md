# M Solar CRM - Complete Project Documentation

## 1. Project Overview
M Solar CRM is a modern, production-grade Customer Relationship Management system designed specifically for a solar energy business. The application provides end-to-end operational control, encompassing lead management, multi-role employee/dealer access, inventory tracking, calendar-based follow-ups, and a robust document management system.

**Tech Stack**:
* **Frontend**: React 18, TypeScript, Vite
* **Styling**: Vanilla CSS with customized design system (glassmorphism, subtle animations, responsive grids)
* **Backend**: Firebase Authentication, Firestore (Database), Firebase Storage (File Uploads)
* **Icons**: Lucide React

---

## 2. Core Architecture

The CRM is built on a highly modular React architecture with centralized state management via React Context.

### 2.1 State Management (`CRMContext.tsx`)
The `CRMContext` is the single source of truth for the application. It manages:
* Real-time listeners for all Firestore collections (`leads`, `users`, `tasks`, `activities`, `stockRequests`).
* Authentication state linking the Firebase Auth user to their Firestore profile.
* Unified data structures to ensure consistency across the Admin, Employee, and Dealer views.

### 2.2 Role-Based Access Control (RBAC)
The application defines three distinct roles, enforced both in the UI and via backend Firebase Security Rules:
* **Admin**: Unrestricted access. Can manage users (Employees & Dealers), view analytics, manage master stock, and oversee all leads.
* **Employee**: Limited access. Can only view and modify leads specifically assigned to them.
* **Dealer**: External partner access. Can only view and manage leads generated by their dealership and submit stock requests.

## 3. Key Feature Modules

### 3.1 Lead Management (`LeadsPage.tsx`)
A comprehensive kanban-style and list-style interface to track solar customers from inception to completion.
* **Status Pipeline**: New → Contacted → Site Visit → Quotation → Negotiation → Closed Won → Closed Lost.
* **Stage Tracking**: Project Lead vs. Document Lead, with granular multi-step progress tracking for installations.

### 3.2 Document Management (Firebase Storage)
* Integrated document uploading directly to Lead profiles.
* Requires files to be strictly `< 10MB` and formatted as `PDF`, `JPG`, or `PNG`.
* Protected by Firebase Storage rules (`isValidDocument()` checks) preventing malicious uploads.

### 3.3 Unified Task & Calendar Engine (`CalendarPage.tsx`)
* A visual Calendar that projects tasks directly from the core `tasks` collection and `leads.followUp` sub-arrays.
* Ensures there is only "one source of truth" for tasks across the entire application, eliminating data duplication.

### 3.4 Stock & Inventory Management (`StockPage.tsx`)
* Real-time tracking of Solar Panels, Inverters, Batteries, etc.
* Dealers can submit `Stock Requests`.
* Admins can approve/reject requests, which automatically deducts from the master inventory and adds to the Dealer's local inventory via atomic Firestore transactions.

### 3.5 Reports & Analytics (`AdminReportsPage.tsx`)
* Dynamically calculated metrics deriving data strictly from real-time Firestore state (no hardcoded mock data).
* Visualizes revenue, lead conversion rates, and employee performance using modern Recharts integrations.

## 4. Security & Production Hardening

The application employs strict production-ready security rules to prevent unauthorized access.

### 4.1 Firestore Rules (`firestore.rules`)
* Strict segregation of duties using `isAuthenticated()`, `getUserRole()`, and `isAdmin()` helper functions.
* Append-only audit logs (`activities` collection).
* Restricted document reads ensuring Dealers and Employees cannot query or intercept data belonging to other organizations.

### 4.2 Storage Rules (`storage.rules`)
* Validates `request.resource.size` and `request.resource.contentType` before accepting any file.
* Restricts folder paths to `leads/{leadId}/documents/{docId}/{fileName}` to maintain structure.

## 5. Deployment & Build

The application is bundled using **Vite**. 
* **Build Command**: `npx tsc --noEmit && npm run build` (Ensures absolute TypeScript strictness before generating the production bundle).
* The output is heavily optimized, though large chunks like Recharts can be dynamically imported if further optimization is required in the future.
